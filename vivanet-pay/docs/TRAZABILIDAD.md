# Trazabilidad de requisitos funcionales (RF-001 a RF-025)

Matriz de los requisitos funcionales del [IDD v1.0 §4.2](IDD_v1.0.md) hacia las clases que los implementan y los tests que los verifican. Las rutas son relativas a `src/main/java/com/vivanetpay/` (clases) y a `src/test/java/com/vivanetpay/` (tests).

Convenciones:

- **Solo Windows**: el requisito depende de API de Windows (bandeja, inicio automático, DPAPI, SAPI). Su prueba automática se omite fuera de Windows (`@EnabledOnOs(OS.WINDOWS)`) o no existe, y hay que verificarlo a mano en un equipo Windows.
- **Manual**: no hay test automatizado; la verificación es una prueba de aceptación con la aplicación.
- **Parcial**: hay cobertura, pero no cubre todo el requisito. Se indica qué falta.

Prioridad según IDD §4.2 (MUST = obligatorio para liberar el MVP; SHOULD = importante, puede diferirse con justificación).

## Huecos de cobertura detectados

1. **Sin test automatizado**: `ui/TrayController.java` y el cierre a bandeja de `ui/MainApp.java` (RF-002, RF-003, RF-004 en su parte de cierre). Requieren prueba manual en Windows.
2. ~~Sin test dedicado a `ConnectorMonitor`~~: resuelto con `application/ConnectorMonitorTest` (RF-025).
3. **Excel no implementado**: RF-020 se cumple solo en su parte CSV (DP-08).
4. **Solo con datos simulados**: Gmail (RF-021) y Android (RF-022). Antes de liberar, probar con una cuenta Gmail de prueba y con un celular real con MacroDroid, según `docs/GMAIL_OAUTH.md` y `docs/MACRODROID.md`.
5. **Dependen de Windows**: `WindowsStartup`, `WindowsSecretStore` (DPAPI, prueba `cifraConElProtectorYLigaElBlobASuClave`) y `WindowsSpeechEngine`. Las pruebas que requieren Windows usan `@EnabledOnOs(OS.WINDOWS)`; en Linux se omiten.
